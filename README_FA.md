# ArzAgent Desktop | آرزایجنت

**اپلیکیشن بومی و گرافیکی فارسی برای Windows و macOS — بدون نیاز به مرورگر و بدون پنجره ترمینال هنگام اجرا**

> **وضعیت نسخه:** کد منبع نسخه اولیه کاربردی (prototype) است. هسته تحلیل و دفتر ثبت سفارش‌ها به‌صورت خودکار تست شده‌اند؛ اما اتصال شبکه صرافی، ظاهر Qt روی Mac/Windows، خروجی اجرایی GitHub Actions و سفارش با پول واقعی در این محیط عملاً تست نشده‌اند. برای استفاده تجاری/سرمایه واقعی، تست صرافی به صرافی، تست یکپارچه و بازبینی امنیتی بیشتری لازم است.

## چه چیزهایی واقعاً پیاده‌سازی شده؟

- رابط گرافیکی فارسی راست‌به‌چپ با **PySide6 / Qt**؛ اپ واقعی دسکتاپ، نه صفحه وب، نه رابط خط فرمان.
- قیمت‌های عمومی بازار از API رسمی صرافی انتخاب‌شده با **CCXT**، هر تقریباً **۱۵ ثانیه**؛ در نبود اینترنت یا در صورت تحریم/محدودیت جغرافیایی داده زنده نخواهد آمد. این **WebSocket یا معاملات فرکانس بالا** نیست.
- انتخاب ۶ صرافی شناخته‌شده: Kraken، Coinbase، Binance، OKX، Bybit و Bitget (قابلیت هر بازار یا حساب باید مستقل بررسی شود).
- فهرست محبوب‌ها و جستجوی همه جفت‌ارزهای Spot فعال دلاری/یورویی همان صرافی.
- سه پروفایل: **بلندمدت (1d)**، **کوتاه‌مدت (1h)**، **نوسان‌گیری (5m)**؛ مقایسه EMA، MACD، RSI، ADX، ATR و فیلتر نوسان/حجم.
- تحلیل فقط روی **کندل‌های بسته‌شده**؛ امتیاز هم‌جهتی تکنیکال از ۱۰۰ **احتمال سود نیست**.
- ایجنت قاعده‌محور که به صورت مستقل پس از دریافت داده سیگنال می‌سازد، ریسک را بررسی و سفارش ثبت می‌کند. **این برنامه چت‌بات هوش مصنوعی یا مدل زبانی مولد و نه مدل پیش‌بینی تضمینی نیست.**
- حالت **Paper** پیش‌فرض، با موجودی فرضی ۱۰٬۰۰۰ واحد ارز دوم در هر حساب/ارز، شبیه‌سازی کارمزد و اسلیپیج.
- حالت **Live Spot** با فعال‌سازی آگاهانه جداگانه، اتصال API خصوصی، بررسی موجودی، حداقل سایز سفارش، کنترل اسپرد و مجوز بازار، خرید و فروش Market، ذخیره سفارش و موجودی ردیابی‌شده؛ **فروش استقراضی، فیوچرز و اهرم ندارد**.
- محدودیت خرید پس از رسیدن به سقف زیان **تحقق‌یافته** در ۲۴ ساعت گذشته، فقط در همان ارز دوم جفت‌ارز؛ این سقف جلوی زیان محقق‌نشده یا پرش قیمت را نمی‌گیرد.
- حد ضرر ATR، حد سود ATR و trailing stop **نرم‌افزاری**؛ تنها تا زمانی‌که اپ باز و متصل باشد فعال‌اند؛ **سفارش Stop-Loss دائمی سمت صرافی نیستند**.
- دفتر ثبت SQLite و کلید یکتای هر کندل برای جلوگیری از ارسال دوباره سفارش پس از ری‌استارت. نتیجه سفارش نامعلوم/timeout باعث **قفل همیشگی خودکار حساب Live** می‌شود تا بررسی دستی تخصصی انجام گیرد. **در این نسخه ابزار بازکردن قفل و همگام‌سازی خودکار موجودی وجود ندارد.**
- ذخیره API Key/Secret/Passphrase در **Keychain macOS** یا **Credential Manager ویندوز** از طریق کتابخانه `keyring`؛ نه در سورس، GitHub یا فایل JSON.
- بک‌تست ابتدایی داده OHLCV گذشته با فرض کارمزد+لغزش ۰٫۱۵٪ در هر سمت، معامله تک‌دارایی با ۲۰٪ سرمایه مجازی؛ معیارهای تاریخی، نه ضمانت سود.
- کد نمونه **Pine Script v6** در `tradingview/ArzAgent_Signals.pine` برای تست آموزشی اندیکاتورهای مشابه روی نمودار TradingView (همسان‌سازی دقیق سیگنال بین دو محیط تضمین نشده است).

## گرفتن خروجی exe و dmg از GitHub (بدون کدنویسی)

1. فایل ZIP دریافتی را Extract / Unzip کنید.
2. در GitHub یک مخزن جدید بسازید. **تمام محتویات** پوشه `ArzAgent-Desktop` را آپلود کنید؛ مخصوصاً پوشه مخفی `.github/workflows/build.yml`، فایل `main.py` و پوشه `arzagent`. فایل ZIP را به‌عنوان یک فایل داخل مخزن نگذارید؛ باید *محتویات* ZIP در ریشه مخزن باشند.
3. وارد مخزن شوید → زبانه **Actions** → گردش‌کار **Build desktop installers** → **Run workflow**. اگر هنگام Push روی شاخه `main`، Actions فعال باشد خودش اجرا می‌شود.
4. پس از اتمام اجرا به همان Workflow Run بروید و از **Artifacts** یکی از این‌ها را دریافت کنید:
   - **ArzAgent-Windows-x64-exe** → فایل `ArzAgent.exe` برای Windows x64
   - **ArzAgent-macOS-AppleSilicon-dmg** → فایل `.dmg` برای Macهای پردازنده M1/M2/M3/M4/…
   - **ArzAgent-macOS-Intel-dmg** → فایل `.dmg` برای مک‌های قدیمی Intel
5. روی ویندوز فایل EXE را اجرا کنید؛ روی مک DMG را باز کنید و آیکن برنامه را به Applications ببرید. این خروجی‌ها **امضای رسمی دیجیتال و notarization اپل ندارند**؛ Windows SmartScreen یا macOS Gatekeeper ممکن است نسبت به برنامه ساخته‌شده شخصی هشدار دهند. بهتر است پیش از اجرای فایل، محتوای سورس و منشأ Build را بررسی کنید و هشدارهای امنیتی را کورکورانه رد نکنید.

**نکته:** GitHub Actions برای ساخت ویندوز از runner ویندوز، و برای مک از runner مخصوص معماری هر مک استفاده می‌کند. ساخت مستقیم exe در مک یا dmg در ویندوز با PyInstaller ممکن نیست.

## اجرای سورس در محیط توسعه (اختیاری)

اگر بعداً بخواهید سورس را تغییر دهید، Python 3.12 روی سیستم توسعه نصب کنید و وابستگی‌های `requirements.txt` را با pip نصب کنید و فایل `main.py` را اجرا کنید. **استفاده روزمره از نسخه exe/dmg هیچ نیازی به Python و ترمینال ندارد.**

## اتصال به صرافی

1. برنامه را باز کنید. بدون کلید API، قیمت زنده صرافی انتخاب‌شده باید نمایش داده شود.
2. در زبانه «اتصال به صرافی» یکی از صرافی‌های پشتیبانی‌شده را انتخاب کنید.
3. در سایت رسمی همان صرافی یک API Key با مجوز **Read** و **Spot Trade** بسازید. مجوز **Withdrawal/Transfer** را خاموش بگذارید. اگر صرافی Passphrase دارد آن را هم وارد کنید.
4. روی «ذخیره امن و آزمایش اتصال» بزنید. امکان ذخیره‌سازی امن و خواندن موجودی بررسی می‌شود؛ این آزمون دسترسی به ثبت سفارش یا مجاز بودن بازار را قطعی نمی‌کند.
5. به «استراتژی و ربات» بروید؛ افق/جفت‌ارز و سقف معامله و حالت را انتخاب کنید. **ابتدا چند روز حالت شبیه‌سازی را بررسی کنید.**
6. برای اجرای واقعی حالت Live را انتخاب کنید، ریسک را تأیید کنید و پس از مطالعه هشدار، شروع را بزنید. این حالت از همان زمان ممکن است **سفارش واقعی بفرستد**؛ سوال جداگانه‌ای برای هر سفارش نمایش نمی‌دهد.
7. برای قطع خودکارسازی، دکمه قرمز توقف را بزنید. اگر نرم‌افزار هنگامی بسته شود که سفارش در حال ارسال است، ابتدا در تاریخچه سفارش صرافی وضعیت واقعی را کنترل کنید.

## TradingView به چه صورت پشتیبانی می‌شود؟

TradingView الگوریتم‌های داخلی خصوصی خود را برای دانلود و اجرای مستقیم به این برنامه ارائه نمی‌کند. آرزایجنت اندیکاتورهای عمومی با منطق قابل ممیزی را در پایتون پیاده‌سازی می‌کند. فایل Pine موجود، یک نمونه مشابه برای پژوهش روی **چارت TradingView** است، نه اتصال سفارش‌گذاری بین این دو برنامه.

برای دریافت Webhook مستقیم از TradingView به یک **سرور HTTPS عمومی امن** (یا سرویس relay با احراز هویت) نیاز دارید. TradingView نمی‌تواند Webhook را مستقیماً به یک اپ دسکتاپ با localhost دلخواه بفرستد؛ فقط پورت‌های ۸۰/۴۴۳ را پشتیبانی می‌کند. **در این نسخه سرویس Webhook عمومی یا Bridge خودکار وجود ندارد.**

## ریسک‌ها و محدودیت‌های مهم

- این نسخه برای تحقیق و توسعه/شبیه‌سازی ساخته شده است. **حتی با وجود منطق سفارش واقعی در کد، به علت نبود آزمون End-to-End نباید بدون بازبینی و تست کامل روی پول واقعی به آن تکیه کرد.**
- اگر پاسخ سفارش نامعلوم باشد، سیستم اجرای Live را **Fail-Closed** می‌کند و بازیابی دستی در UI ندارد؛ دست‌کاری پایگاه داده برای رفع قفل، بدون تطبیق دقیق با صرافی، می‌تواند سفارش تکراری یا اختلاف موجودی ایجاد کند.
- قیمت ۱۵ ثانیه‌ای برای معاملات فوق‌سریع مناسب نیست. ارتباط شبکه، تأخیر، اختلاف قیمت و بازارگردانی صرافی متفاوت است.
- سفارش Market ممکن است به قیمتی متفاوت از آخرین قیمت نمایش‌داده‌شده پر شود، یا با پرداخت کارمزد اضافی همراه باشد.
- **سقف ریسک حداکثر زیان را تضمین نمی‌کند**؛ حد ضرر سمت سرور صرافی پیاده‌سازی نشده، و قطعی اینترنت/برنامه ریسک باز ماندن معامله را دارد.
- هر صرافی محدودیت‌های منطقه‌ای، جفت‌ارزهای متفاوت، نیاز به KYC و قوانین خاص دارد. اجرای موفق با یک صرافی به معنای اجرای موفق با همه نیست.
- بک‌تست برای بررسی اولیه است، نه ارزیابی جامع Walk-forward/Monte Carlo و نه شبیه‌سازی دقیق دفتر سفارش، مالیات یا شرایط نقدشوندگی.
- بخشی از خطاهای شبکه/صرافی ممکن است دسترسی به داده یا اتصال API را مختل کند. هیچ رمز خصوصی یا Seed Wallet را هرگز در برنامه وارد نکنید.

## اطلاعات فنی

- `main.py`: ورود اپ
- `arzagent/ui.py`: رابط کاربری Qt
- `arzagent/agent.py`: گردش دریافت اطلاعات، تصمیم‌گیری و سفارش
- `arzagent/strategy.py`: شاخص‌ها و سیگنال‌ها
- `arzagent/backtesting.py`: بک‌تست تاریخی
- `arzagent/exchanges.py`: قابلیت‌های CCXT و انتخاب بازار
- `arzagent/storage.py`: ذخیره امن اعتبارنامه‌ها / SQLite
- `tests/`: تست‌های واحد
- `.github/workflows/build.yml`: بسته‌بندی خودکار Windows و macOS
- `tradingview/ArzAgent_Signals.pine`: استراتژی مستقل آموزشی Pine
